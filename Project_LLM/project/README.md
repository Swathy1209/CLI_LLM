# Agentic Multi-Source Retrieval System

A command-line application that answers business questions by intelligently
selecting relevant data sources and generating cited, accurate responses
using the Groq API.

---

## Quick Start

### 1. Install dependencies

```bash
pip install groq
```

### 2. Set your API key

```bash
export GROQ_API_KEY=your_key_here
```

### 3. Run the agent

```bash
python agent.py
```

You will see a prompt:

```
Enter your question:
```

Type any business question and press Enter. Type `exit` or `quit` to stop.

---

## Example Questions

```
Why did revenue decrease last month?
Compare salary expenses with sales revenue
Provide a brief summary of business performance
Which region has the highest returns?
How has headcount changed over the past few months?
What is the outlook for Q1 2025?
```

## Approach and Architecture

The system follows a three-step agentic pipeline:

```
User Question
     │
     ▼
┌─────────────────────┐
│  Source Selection   │  Keyword-based routing decides which files to load
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐
│   Data Loading      │  CSV → numbered row table  |  TXT → numbered paragraphs
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐
│   Groq API Call    │  Full data + citation instructions sent as a prompt
└────────┬────────────┘
         │
         ▼
  Cited Answer printed to terminal
```

---

## Source Selection Logic

Source selection is performed by `select_sources()` in `agent.py`.

Each data source has an associated keyword list defined in `SOURCE_ROUTING`:

| Source        | Trigger keywords (examples)                              |
|---------------|----------------------------------------------------------|
| `sales.csv`   | revenue, sales, units, product, region, widget, returns  |
| `payroll.csv` | salary, payroll, headcount, employee, bonus, department  |
| `report.txt`  | summary, overview, why, reason, cause, explain, trend    |

The function scores each source by the number of its keywords that appear
in the user's question. Any source with a score > 0 is included. In
addition, questions containing reasoning words (`why`, `how`, `reason`,
`explain`, `summary`, `overview`) always include `report.txt` to provide
narrative context even if not explicitly scored.

If no source scores above zero, all three sources are used as a fallback.

The decision is printed to the terminal before the API call:

```
[Agent Decision]
  - Using sales.csv for numerical / structured analysis
  - Using report.txt for narrative context and explanations
```

---

## Citation Method

Citations are generated by the LLM itself via prompt engineering.

The system prompt instructs the model to end every response with a
`Sources:` section using this format:

```
Source: sales.csv (rows 5–12)
Source: report.txt (paragraph 3)
```

To make this possible:

- **CSV files** are loaded with explicit row numbers prepended to each line,
  so the LLM can reference exact row ranges.
- **Text files** are split into paragraphs and each paragraph is tagged with
  a `[Paragraph N]` label before being sent to the model.

This approach ties every factual claim back to a specific, verifiable
location in the source data.

## Data Description

### `sales.csv`
Monthly sales records (August–November 2024) broken down by region
(North, South, East, West), product (Widget A/B/C), units sold, unit price,
gross revenue, returns, and net revenue.

### `payroll.csv`
Monthly payroll records (August–November 2024) broken down by department
(Sales, Engineering, Marketing, Operations, HR), employee count, base
salary, bonuses, benefits, and total expense.

### `report.txt`
A narrative Q4 2024 business performance report covering executive summary,
revenue trends, South region decline, salary/headcount analysis, operational
highlights, and Q1 2025 outlook. Split into labelled paragraphs for citation.
